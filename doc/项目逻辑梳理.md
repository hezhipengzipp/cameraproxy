# CameraProxy 项目逻辑梳理

## 一、项目定位

**多进程相机共享框架** —— 让一路摄像头的数据**零拷贝**同时送给多个 App 订阅。

核心目标：单个相机独占的 Service 在独立进程中管理，通过 AIDL 暴露订阅接口，使多个客户端 App 能够并发共享同一路摄像头数据流，无需重复打开 / 关闭摄像头。

## 四、关键流程

### 1. 初始化链路

```
Client bindService("ACTION_BIND")
  → CameraHolderService.onBind()
  → 返回 ICameraProxyService.Stub()
```

### 2. 相机数据流

```
Camera Device
  → CameraCaptureSession(固定 SurfaceTexture)
  → OES 纹理 ID（GL 线程）
  → glDraw 逐个 blit 到订阅者的 EGLWindowSurface
  → eglSwapBuffers 直写客户端 Surface（无内存副本）
```

### 3. 订阅管理

- `subscribe(Surface, Callback)` 返回唯一 subscriberId
- Binder 异常监听（`linkToDeath`）自动释放订阅
- 所有订阅者移除时 → 自动关闭摄像头

## 八、核心创新点

通过 **SurfaceTexture + OpenGL fan-out**，零拷贝直送多个订阅者 Surface，避免：

1. 重复打开摄像头导致的资源浪费
2. Session 重建引起的黑屏闪烁
3. CPU 参与 YUV → RGB 转换的性能开销

---

## 九、OpenGL ES 2.0 + GL_TEXTURE_EXTERNAL_OES 技术详解

### 9.1 为什么需要 OES 外部纹理？

Camera2 / MediaCodec 输出的是 **YUV** 格式（NV21/YUV420）的硬件 buffer，而普通 `GL_TEXTURE_2D` 只能处理 **RGBA**。直接用 2D 纹理需要 CPU 做 YUV → RGB 转换，**性能差且耗电**。

OES 扩展 `GL_OES_EGL_image_external` 让 GPU **直接采样 GraphicBuffer**（BufferQueue 里的原生 buffer），驱动内部完成颜色空间转换，**零拷贝、零 CPU 参与**。

### 9.2 与普通 2D 纹理的核心差异

| 维度        | GL_TEXTURE_2D          | GL_TEXTURE_EXTERNAL_OES                     |
| ----------- | ---------------------- | ------------------------------------------- |
| 数据源      | 应用内存上传（glTexImage2D） | BufferQueue 的 GraphicBuffer          |
| 格式        | RGBA                   | 任意（YUV/RGB，由驱动转）                   |
| Shader 类型 | `sampler2D`            | `samplerExternalOES`                        |
| 扩展声明    | 不需要                 | `#extension GL_OES_EGL_image_external : require` |
| 上传方式    | `glTexImage2D`         | `SurfaceTexture.updateTexImage()`           |
| 绑定目标    | `GL_TEXTURE_2D`        | `0x8D65`（GL_TEXTURE_EXTERNAL_OES）         |

### 9.3 数据管线（对照 CameraEngine）

```
Camera HAL
  │ 写入
  ▼
GraphicBuffer (BufferQueue)            ← SurfaceTexture 持有消费端
  │ updateTexImage()                    CameraEngine.kt:269
  ▼
OES 纹理 (oesTextureId)                 ← createOesTextureId() 创建
  │ samplerExternalOES 采样
  ▼
Fragment Shader 绘制                    CameraEngine.kt:291
  │ eglSwapBuffers(订阅者 Surface)      CameraEngine.kt:292
  ▼
订阅者 App 的 SurfaceView
```

### 9.4 关键代码点评

#### (1) OES 纹理创建（OesTextureProgram）

```kotlin
GLES20.glGenTextures(1, tex, 0)
GLES20.glBindTexture(GL_TEXTURE_EXTERNAL_OES, tex[0])  // 关键！绑定到 OES target
GLES20.glTexParameteri(GL_TEXTURE_EXTERNAL_OES, GL_TEXTURE_MIN_FILTER, GL_LINEAR)
// 必须 CLAMP_TO_EDGE —— OES 不支持 REPEAT
GLES20.glTexParameteri(GL_TEXTURE_EXTERNAL_OES, GL_TEXTURE_WRAP_S, GL_CLAMP_TO_EDGE)
```

#### (2) Shader 特殊写法

```glsl
#extension GL_OES_EGL_image_external : require   // 必须声明
precision mediump float;
uniform samplerExternalOES sTexture;             // 不是 sampler2D！
uniform mat4 uTexMatrix;                         // 处理翻转/旋转
varying vec2 vTexCoord;
void main() {
    gl_FragColor = texture2D(sTexture, vTexCoord);
}
```

#### (3) stMatrix 变换矩阵（CameraEngine.kt:270）

```kotlin
st.getTransformMatrix(stMatrix)
```

**必须用**：相机输出的纹理坐标**天然是翻转的**（原点在左下 vs. 屏幕左上），且可能涉及传感器方向。这个 4×4 矩阵由 SurfaceTexture 提供，Shader 内 `texCoord * uTexMatrix` 自动校正。不用就会画面倒置。

#### (4) Fan-out 多订阅者（CameraEngine.kt:276-299）

**这是项目的核心创新**：

```kotlin
for (bind in subscribers.values) {
    core.makeCurrent(dst)              // 切换到订阅者的 EGLWindowSurface
    prog.draw(oesTextureId, stMatrix)  // 同一个 OES 纹理
    core.swapBuffers(dst)              // 提交到订阅者 Surface
}
```

**同一个 OES 纹理**（唯一 GraphicBuffer）被**多个 EGLSurface** 反复绘制。每次 `makeCurrent` 切换绘制目标，但采样源不变 —— 真正实现「一路采集、多路分发」的零拷贝。

### 9.5 关键约束与陷阱

| 约束                                         | 后果                                               |
| -------------------------------------------- | -------------------------------------------------- |
| OES 纹理采样**必须**在 GL 线程               | 跨线程需 `eglMakeCurrent`                          |
| `updateTexImage()` 必须有当前 GL context     | CameraEngine.kt:267 先 `makeCurrent(dummyPbuffer)` |
| OES 不支持 **mipmap** / **REPEAT 环绕**      | 必须 CLAMP_TO_EDGE + LINEAR                        |
| 同一 GraphicBuffer 不能被两个消费者同时锁定  | 所以用 GL fan-out，而非多个 SurfaceTexture         |
| `uTexMatrix` 每帧可能变                      | 必须每次 `getTransformMatrix` 后传给 Shader        |

### 9.6 为什么选 GL 方案而不是 ImageReader？

- `ImageReader + YUV` → 每帧 CPU 拷贝 + 手动 YUV 转码，单订阅就卡顿
- `多个 Surface 直接挂到 CaptureSession` → Camera2 输出 Surface 数量有限（通常 ≤ 3），且重建 Session 会**黑屏闪烁**
- **GL fan-out** → 订阅者增减只动 EGLSurface，**不碰 CaptureSession**（CameraEngine.kt:26-27 的设计初衷）
